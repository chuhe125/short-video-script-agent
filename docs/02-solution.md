# 流程、动态决策与技术取舍

采用Python标准库：urllib调用DeepSeek，hashlib生成脚本版本哈希，unittest测试。没有Agent框架依赖，不需要数据库或其他题目的文件。

## 真实模型循环

1. 校验用户输入，生成编辑brief，包含语速、画幅、镜头建议、停顿上限与品牌禁词。
2. DeepSeek通过原生函数调用选择一个业务动作；工具定义search/write/estimate/check/finish，参数含简短reason。
3. 执行器校验参数白名单后执行本地工具，记录真实返回；每次观察都冻结快照。
4. 再次将输入和累计观察交给模型，由新响应选择修正、补查、重试或结束。
5. finish仅能在当前稿的时长和规则检查均通过时返回completed；模型自己声称通过不起作用。

为简化状态重放，每次请求用system指令和user中的结构化输入/历史Trace重建上下文；不依赖服务端对话。原生函数调用返回由客户端解析，工具结果在下一请求的Trace中提供，没有伪造assistant工具消息。

串行调度器只执行模型响应中的第一个函数调用。若响应还提出其他调用，原始函数参数保留在execution.model_calls，未执行名称记录在unexecuted_calls；下一轮必须重新向模型决策，不能将未执行调用记成工具成功。这保证工具上限与依赖观察明确。

## 事实与编辑边界

素材有ID、日期、fact、approved_lines。approved_lines是从合成事实扩写并预先审核的有限表达，模型只能选择和组合，不能任意生成产品效果。check逐字核对来源表达，并检查品牌禁词、画面类型和单镜头静默停留上限。该策略牺牲自由度，避免把字符串引用存在误当成任意结论有依据。

用户新手受众的估算语速为基础4字符/秒的0.875倍，专业受众为1.125倍，其他为基础值；B站/横屏用16:9，其他默认9:16；教程/活泼/简洁影响画面建议、标题及停顿。这些是原型启发式，不是平台官方标准，也不宣称来自模型推断。

模型获得brief后选择实际分镜。旁白字符数（含标点）/估算语速 + hold_seconds得到镜头时长，逐场景四舍五入到两位再求和。estimate还返回超时秒数与建议总停顿预算；模型可参考建议，也可作其他符合规则的修正。没有执行器自动压缩真实模型稿。

## 状态与可核验结果

write复制候选分镜并记录版本哈希，清空旧duration/review。estimate和check都绑定当前哈希。最终输出时间轴、字幕、来源原文、版本、风险、缺口、修订历史和工具错误。失败产物保留但不标completed。

默认16次决策，最多30次；finish也计入决策。实际工具执行次数另计，工具失败同样计入。模型调用失败则保留部分结果并返回model_error；不在执行器中自动重试。业务故障由模型看到错误后选择重试或结束。

## 取舍与实测改进

最初的文本JSON动作协议在真实调用中出现reason错位、多个JSON对象、尾部标记；进一步的通用select_action包装也出现字段缺失。最终改为直接业务函数调用，并记录原始函数参数。没有从任意文本中截取一个看起来成功的JSON，也不保存reasoning_content。之前失败记录保留在examples/history。

当前没有使用beta strict模式，客户端仍严格检查参数；原生调用不等于服务端保证全部业务参数正确。源资料和用户请求属于数据，不允许指示工具越权。未对任意提示注入做全面验证。
