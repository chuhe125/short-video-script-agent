# 回顾、学习与下一步

## 已记录的工程观察

原版本将30秒稿从40秒压缩为4秒，满足上限但不够实用。优化后在不增加产品事实的情况下，将预审表达与可解释的演示停顿分开处理，增加分镜时间轴、来源原文及素材日期；Mock修正为27秒，真实模型实测为38.43秒→26.93秒。

最重要的工程边界是检查属于某一版本脚本。write后旧的时长与规则结果必须失效；候选稿、通过检查、任务完成是不同事实。工具失败或模型错误发生后仍应保留素材和候选稿，但不能虚报completed。

真实调用暴露了离线测试没覆盖的协议问题：多个JSON对象、尾部标记、动作字段缺失与并行工具调用。最终采用直接业务函数调用，严格校验参数，并将未执行的并行提议明确记录后交给下一步模型重新决策。历史失败没有改写为成功。

标准库原生实现便于审查，框架本身不是主要难点。来源边界、观察驱动修正、失败语义和可核验运行记录更值得优先完成。
